# Карта экранов: выбор Типа события на `/events`, слоты на `/booking`, владелец на `/upcoming`

Посетителю нужен отдельный шаг выбора Типа события перед календарём слотов: кнопка «Записаться» на Главной ведёт в каталог видов звонков, а не сразу в календарь. Из-за этого Предстоящие события — взгляд владельца — не могут больше жить на `/events`.

Решено:

- `/` — Главная страница;
- `/events` — выбор Типа события (посетитель): список типов с описанием и длительностью, выбор ведёт к Записи;
- `/booking` — страница Записи (посетитель): слоты выбранного Типа события, контакт, подтверждение;
- `/upcoming` — Предстоящие события (владелец): журнал Записей и управление Типами событий;
- навигация в шапке: «Записаться» → `/events`, «Предстоящие события» → `/upcoming`.

## Considered Options

- Выбор Типа события внутри страницы Записи (`/booking`) — исходная редакция спеки; отклонено: посетителю нужен отдельный шаг выбора.
- Одна общая страница `/events` для каталога и раздела владельца — отклонено: смешивает взгляды посетителя и владельца.

## Consequences

- ADR-0001 (vue-router в history-режиме) сохраняет силу: адреса остаются чистыми.
- Управление типами (тикет #17) переезжает с `/events` на `/upcoming`; `/events` становится каталогом для посетителя.
- Спецификация (`docs/spec.md`, issue #15) и тикеты реализации #18/#20 приведены в соответствие.
